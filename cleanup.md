# Уборка после задачи

Решение владельца: закончив задачу, ведущий прибирается за собой — удаляет всё, что задача создала и что больше не нужно. Цель: на каждой машине по любой папке видно, чья она и можно ли её удалить, а диск не забивается копиями, сборками и временными файлами.

## 1. Папка задачи

- Всё, что задача создаёт вне постоянных мест, лежит в одной папке задачи на каждой машине: `<корень задач>/<id задачи>/`. Это рабочие копии (`git worktree`), клоны, деревья сборки, копии для стендов, временные файлы. Корни задач и список постоянных мест (основная копия владельца, стенды, общие клоны, места помощников) — в памяти проекта.
- Карточка запуска называет папку задачи на каждой машине (строка «Рабочие места»), задание исполнителя — тоже, текстом. Место вне папки задачи — только по ответу ведущего на `Q`; ведущий дописывает его в карточку.
- Временные файлы — в `<папка задачи>/tmp`: запуская исполнителя, ведущий задаёт `TMPDIR`, `TEMP` и `TMP`. Системные `/tmp` и `%TEMP%` задача не использует.
- Новая полная копия исходников — только если нельзя обойтись `git worktree add` от уже имеющегося клона; одновременно — не больше одной на задачу. Большие артефакты (сборки, дампы, модели) — в одном экземпляре.
- Субагенты ведущего пишут в свои подпапки временной папки ведущего (SKILL.md §9). Рабочие копии git там не создаются: им место в папке задачи.

## 2. Сдача

В `DONE` — раздел «Рабочие места»: каждый путь, который создала задача (и вне папки задачи тоже), его размер (`du -sh`) и что это:
- **доказательство** — на него ссылаются DONE, PR или журнал: логи прогонов, `prompt-review`, выжимки;
- **промежуточное** — сборка, клон, кэш, временные файлы.

Объекты сборки, которые не нужны для повторной проверки, исполнитель удаляет сам после последнего прогона на них и пишет это в разделе. Остальное до закрытия задачи не трогает.

## 3. Закрытие: уборка

Уборка — часть закрытия задачи (SKILL.md §3 п. 8), в том же шаге после слияния или приёма. Решает ведущий, механику делает скрипт `~/.claude/skills/team-process/tools/task-places.py`.

1. **Доказательства — наружу.** Файлы, на которые ссылаются DONE, PR и журнал, уже лежат в репозитории или переносятся в архив доказательств проекта (путь — в памяти проекта). Остальное в папке задачи — мусор.
2. **Опись:** `python ~/.claude/skills/team-process/tools/task-places.py inventory <пути> --refs <живые файлы> --size`. По каждому месту: вид (рабочая копия, клон, папка), ветка и дата последнего коммита, размер, незакоммиченные и неотслеживаемые файлы, коммиты, которых нет на удалённом, процессы внутри (только Linux), ссылки из живых файлов. Живые файлы — текущий план, задания и цели идущих задач, документы репозитория, память проекта; файлы самой закрываемой задачи не передаются. Место на другой машине сверяется со ссылками обеих машин: путь, которого на этой машине нет, скрипт тоже ищет в ссылках.
3. **Удаление:** `python ~/.claude/skills/team-process/tools/task-places.py remove <пути> --refs <живые файлы> --archive <архив>`, сначала с `--dry-run`. Скрипт сохраняет в архив `HEAD`, полный diff, неотслеживаемые файлы и bundle коммитов, которых нет на удалённом, затем удаляет: рабочую копию — `git worktree remove` и `prune`, остальное — по точному пути. Скрипт отказывает, если на место ссылается живой файл, внутри работает процесс, у клона есть связанные рабочие копии, у копии нет удалённого или неотслеживаемые файлы больше 100 МБ. Отказ не обходить: убрать ссылку, перевести место в постоянные или спросить владельца.
4. **Ветки.** Слитую ветку задачи удалить локально (`git branch -d`, не `-D`) и на удалённом — при слиянии (`--delete-branch`). Долгоживущие ветки из памяти проекта не трогать.
5. **Запись.** В записи закрытия — строка «Уборка: удалено N мест, освобождено X ГБ, архив <путь>; оставлено <путь> — <почему>».

**Разрешение.** То, что создала сама задача и что прошло опись, ведущий удаляет без отдельного «да» владельца: это и есть решение владельца. Постоянное, общее и чужое место (другой задачи, помощника, владельца), а также место неизвестного происхождения — только списком владельцу по описи скрипта; удаление — по его «да» на этот список. Широкие команды удаления (SKILL.md §9) запрещены и здесь.

## 4. Старые завалы и место на диске

- Место без папки задачи или из закрытой задачи, найденное по ходу работы, — в опись и списком владельцу в тот же день.
- Свободного места на машине меньше порога из памяти проекта — до новой большой работы сначала уборка по описи.
- Список на удаление показывается владельцу только по описи скрипта, со ссылками, процессами и несохранёнными правками по каждому месту: список по дате и имени без проверки ссылок ломает идущую работу.
